# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A [Pi coding agent](https://pi.dev) extension (`@earendil-works/pi-coding-agent`) that disables Pi's built-in `bash` tool and replaces it with structured, single-purpose filesystem tools — for smaller/weaker models that do better with constrained tools than a raw shell.

No build step: `index.ts` and everything under `src/` run directly via Node 24's native TypeScript type-stripping, in both the extension and its tests.

## Commands

- Run all tests: `npm test` (runs `node --test src/tests/**/*.test.ts`)
- Run a single test file: `node --test src/tests/find.test.ts`
- Type-check without emitting: `npx tsc --noEmit`
- Try the extension in a live Pi session without installing it: `pi -e ./index.ts`

There is no lint or build script.

## Tool structure

Each tool (`find`, `grep`, `list`, `edit`, `mkdir`, `remove`, `copy`, `move`, `lstat`, `insert`, `read`, `peek`, `write`, `git_status`, `git_diff`, `git_log`, `ts_lib`, `py_lib`, `py_list`, `dotnet_lib`, …) is split into two files that must stay in sync:

- `src/tool_definitions/<tool>.ts` — the static `*_TOOL_DEFINITION`: name, description, `promptSnippet`/`promptGuidelines` shown to the model, and the typebox `parameters` schema.
- `src/tools/<tool>.ts` — spreads the definition into `pi.registerTool({...})` and implements `execute()`. Each file also exports a plain async function (`findFiles`, `grepFiles`, `listDir`, `editFile`, `makeDir`, `removePath`, `copyFile`, `moveFile`, `lstatPath`, `insertText`, `readFile`, `peekFile`, `writeFile`, `gitStatus`, `gitDiff`, `gitLog`) that does the real work independent of `ExtensionAPI` — this is what `tests` calls directly. `grep` also has `src/tools/grepWorker.ts` (see below).

`index.ts` registers all of these tools, then on `session_start` filters `bash` out of the active tool list. `find`/`grep`/`edit`/`read`/`write` share names with Pi's built-ins and replace them automatically (same-name registration wins per Pi's tool registry); `list`/`mkdir`/`remove`/`lstat`/`insert`/`peek`/`git_status`/`git_diff` have no built-in collision. `index.ts` also registers `/toggle-sandbox` (see below) and resets sandbox state to `"on"` on every `session_start`, since it's a process-lifetime variable, not a per-session one.

## Sandboxing

- **`src/pathSafety.ts`** — `resolveSafePath(root, target)`: the hard, non-toggleable containment primitive. Checks (1) lexical `..`-traversal/absolute-path escape and (2) a symlink-aware recheck (resolves both `root` and `target` to their real paths and reverifies containment), closing the gap where an in-root symlink points outside it. Targets that don't exist yet (e.g. `mkdir`) are handled by resolving only the nearest *existing* ancestor and reattaching the missing suffix lexically. Also exports `isEntryWithinBase(base, entryPath)`, the same check applied to an already-discovered entry. **Only `sandbox.ts` calls this file** — no tool imports it directly.
- **`src/sandbox.ts`** — `resolveSandboxPath(root, target, mode)` is what every tool's `execute()` actually calls (`mode` is `"read"` for `find`/`grep`/`list`/`lstat`/`read`/`peek`/`git_status`/`git_diff`, `"edit"` for `write`/`edit`/`insert`/`remove`/`mkdir`). It wraps `resolveSafePath` with a second, mode-aware layer: `READ_RESTRICTED_GLOBS` (SSH keys, `.aws`, `.env*`, `.netrc`, `.npmrc`, `.pgpass`, `.docker`, `.kube`, `.gnupg`, gcloud config, private-key filenames, and `.git/**`) blocks credential access in both modes — `.git/**` is included because `.git/config` routinely embeds credentials in remote URLs and `.git/objects`/`packed-refs` can retain secrets long deleted from the working tree, so it's a disclosure risk, not just a mutation one; `find`/`grep`/`list`'s default ignore globs keep `.git` out of an *unscoped* walk, but that's a convenience, not a security boundary, since it does nothing once a call points `path` straight at `.git`. `EDIT_RESTRICTED_GLOBS` is currently identical to `READ_RESTRICTED_GLOBS`. Globs are matched against both the lexical and real (symlink-resolved) path, so a symlink disguising itself as something else is still caught. A module-level `SandboxState` (`"on"`/`"off"`, default `"on"`) gates all of this: `"off"` disables root-containment *and* restricted globs — see `src/permissionGate.ts` for what fills that gap. Set via `/toggle-sandbox` (no argument toggles `on`/`off`). `isEntrySandboxSafe(base, entryPath, mode, isSymlink)` is the same check applied to entries a directory walk *discovers* (see below), and accepts an optional `stateOverride` for callers that don't share this module's in-memory state (namely `grepWorker.ts`, which runs in its own thread with its own copy starting at `"on"`).
- **Directory-walk entries aren't covered by a single `resolveSandboxPath` call.** `find`/`grep`/`list` glob or `readdir` beneath an already-safe base, and a symlink in that tree can point outside it even though the base passed. `fast-glob`'s `followSymbolicLinks: false` only stops *descending into* a symlinked directory, not excluding a symlinked file from the results. `find.ts`/`grep.ts` request `objectMode: true` from fast-glob (free `dirent` access) and drop any entry failing `isEntrySandboxSafe`; `list.ts`'s manual `readdir` walk does the same, and never recurses into a symlinked directory since `Dirent.isDirectory()` is false for one.
- **`src/permissionGate.ts`** — this project's own on/off decision system, built directly on Pi's `ExtensionAPI` (`pi.on("tool_call", ...)` plus `ctx.ui.confirm`) and registered once in `index.ts`, with no session lifecycle needed. While sandbox state is `"on"`, it does nothing — `sandbox.ts` already fully enforces containment locally. While `"off"`, it intercepts every call to one of this project's tools (the `GATED_TOOL_NAMES` set, which includes `peek`) before it runs and requires an explicit `ctx.ui.confirm()` approval (one-shot, not remembered); declining blocks the call with a reason the model sees, and a non-interactive context (`ctx.hasUI === false`) blocks automatically since there's no one to ask. An earlier version of this file tried to integrate with the separate `@gotgenes/pi-permission-system` extension via a `registerAuthorizer` hook so `"on"` could auto-suppress a second prompt from that extension; that hook doesn't exist on the package's actual public API (it only exposes `checkPermission`/`getToolPermission` and prompt-text formatting hooks, confirmed by reading the installed package's own docs), so the integration silently never worked. This file replaces it and needs no other extension installed.

## Per-tool notes

- **`edit`** — single `{path, oldText, newText}` per call (not Pi's built-in batched `edits` array); `oldText` must match exactly one location or it throws, unless `allowMultipleMatches: true`. Both content and `oldText`/`newText` are LF-normalized before matching (so `\n`-written text still matches a CRLF file and vice versa), and the file's original line-ending style is reapplied on write.
- **`insert`** — inserts text after a 1-indexed `line` (matching `grep`'s numbering) without touching existing content; `line: 0` inserts before the first line, `line` equal to the file's line count appends at the end. Preserves the file's existing CRLF/LF style.
- **`read`** — replaces Pi's built-in (text-only, no image support). `offset`/`limit` select a line range; output is additionally capped at 2000 lines/50KB (`DEFAULT_MAX_LINES`/`DEFAULT_MAX_BYTES` in `src/tools/read.ts`). `truncated` is set whenever the range stops short of the file's end, with a `[Showing lines X-Y of Z. Use offset=N to continue.]` hint. Read-only, so it skips the mutation queue (see below). `readProjectFile(root, target, opts)` is its sandboxed entry point (`resolveSandboxPath(..., "read")` then `readFile`), used by `read`'s own `execute()` and by every tool that reads file contents on top of read (`peek`); `ReadOptions.uncapped` is an internal-only flag (not in the tool schema) that skips the line/byte caps for such callers.
- **`peek`** — a structural outline of one file instead of its contents; `path` alone gives the default view (public declarations, no bodies, no docs). Line numbers match `read`/`grep`/`insert`, so a model can peek and then `read` a specific body with `offset`/`limit`. Peek mode is chosen purely by file extension via `src/tools/previewManagers/registry.ts`; an unsupported extension (or a directory/binary file) throws with a hint to use `read`. Optional params: `visibility` (`"public"` default / `"protected"` / `"private"`, inclusive — `"private"` shows everything), `includeDocs` (full docstrings/JSDoc/`///` XML docs), `maxDepth` (Markdown only, heading levels 1-6). Output is capped like `read` (2000 lines/50KB) with a `[Outline truncated …]` hint. **Never touches the filesystem itself**: `peekFile(root, target, opts)` gets the file's lines only via `read.ts`'s `readProjectFile` (with `uncapped: true`), so it inherits read's sandboxing (root containment, symlink escapes, restricted globs, sandbox on/off) and line numbering exactly. Read-only, skips the mutation queue. See "PreviewManagers" below.
- **`write`** — mirrors Pi's built-in (create/overwrite, `mkdir -p` parents first) but goes through `resolveSandboxPath` (mode `"edit"`) first, which the built-in doesn't.
- **`remove`** — refuses to delete a directory without `recursive: true`, and refuses to delete the project root outright (a `projectRoot` option on `removePath` itself, checked before even `lstat`-ing the target, so it's covered by the same plain-function tests as everything else).
- **`copy`** — refuses to copy a directory without `recursive: true`, and refuses to replace an existing `destination` without `overwrite: true`. Only `destination` goes through `withFileMutationQueue`; `source` is only ever read (via `fs.cp`), so a concurrent edit/write/remove targeting it isn't blocked, same tradeoff `remove` accepts for paths outside its literal target.
- **`move`** — same `recursive`/`overwrite` gating as `copy`, but renames via `fs.rename` (falling back to `fs.cp` + delete-source on `EXDEV`, i.e. source and destination on different filesystems) since `source` is mutated too. Both `source` and `destination` go through `withFileMutationQueue`, always locked in the same lexically-sorted order regardless of call direction, so two moves swapping the same two paths can't deadlock waiting on each other's lock. Also refuses to move the project root itself (same `projectRoot` guard as `remove`).
- **`mkdir`** — always `mkdir -p` semantics (creates missing parents, no-ops if it already exists).
- **`lstat`** — never follows symlinks; reports `isSymbolicLink` rather than resolving through it.
- **`find`/`grep`/`list`** — all return a `{..., total, truncated}` shape and cap output at `maxResults` (default 200). `truncated` is only set once the scan finds one match/entry *beyond* the cap, so an exact-boundary result isn't wrongly flagged.
- **`grep`** — the scan loop runs off the main thread in `grepWorker.ts`, since a catastrophically-backtracking regex (e.g. `(a+)+$`) can only be stopped by killing its thread, not by checking an `AbortSignal` mid-scan. `grepFiles()` glob-expands and sandbox-filters on the main thread, then hands the file list (plus a `sandboxState` snapshot) to a fresh `Worker` and races it against a 5s wall-clock timeout (`DEFAULT_TIMEOUT_MS`, not tool-exposed); on timeout/abort the worker is `terminate()`d. The worker re-checks `isEntrySandboxSafe` itself before reading each file rather than trusting the main thread's pre-filter, reusing the `isSymlink` flag it was handed to avoid a redundant `lstat`.
- **`git_log`** — `git log --name-only` with a custom `%x1e`/`%x1f`-separated format, parsed into `{hash, author, date, subject, files}`; `maxCount` defaults to 10 and is clamped to 50. Each commit's file list is filtered through `isEntrySandboxSafe`; an empty repo returns no commits instead of erroring. Read-only, skips the mutation queue.
- **`git_status`/`git_diff`** — the only tools that don't touch the filesystem directly; they shell out to `git` via `execFile` (array args, no shell, no injection surface), `cwd` pinned to the project root. `git_status` parses `git status --porcelain=v1 --branch` into `{branch, ahead, behind, entries}`. `git_diff` runs plain `git diff` (unstaged only) through the same truncation cap `read` uses. Both accept an optional `path` to scope the call, sandboxed (mode `"read"`) when passed — but **also** filter their parsed results against the restricted-globs list on every call, scoped or not, so a tracked `.env` with an uncommitted change can't leak its path via `git_status` or its content via `git_diff` just because no `path` was given. Read-only, so both skip the mutation queue.
- **`dotnet_list`/`npm_list`/`ts_check`/`py_list`/`py_lib`** — shell out through `src/runCommand.ts`'s `runCommand` (array args, no shell). Node's promisified `execFile` *rejects* on a non-zero exit (there is no `reject: false` option — that's execa's API, and an earlier version of these tools passed it anyway, so a failing `npm list`/`tsc` lost its real output); `runCommand` turns that rejection back into `{stdout, stderr, exitCode}`, throws `CommandNotFoundError` on ENOENT, and rethrows `AbortError`.

## Library tools (`ts_lib`, `py_lib`, `dotnet_lib`, `src/tools/libInfo/`)

Describe the API of an installed package in the version actually installed. All three take the same parameters (`src/tool_definitions/libShared.ts`): `package` (required), `module`, `symbol`, `query`, `includeDocs`, `maxResults`. The view is picked by which are present (`libInfo/query.ts` `selectView`): `symbol` → that symbol's declarations (overloads) with full docs, plus its members with one-line summaries; `query` → ranked case-insensitive substring search over dotted names; neither → overview (info header + direct children of `rootContainer`). Symbol lookup is exact, then dotted-suffix, then case-insensitive; more than 3 distinct matches gives a "which one?" list, none gives suggestions. `normalizeSymbol` accepts `Foo.bar()`, `Foo<T>.bar`, `Foo::bar`, `Foo#bar`, `Foo.prototype.bar`. `libInfo/format.ts` renders plain text capped like `read` (2000 lines/50KB).

Each language only produces a `LibExtraction` (`libInfo/types.ts`): `LibraryInfo` (version, location, API source files, summary, dependencies, modules, notes) and a flat `ApiEntry[]` (`kind`, `name`, `container` = dotted parent, `signature`, `docs`, `source`/`line`, `reexportedFrom`).

**Sandboxing**: installed packages often live outside the project root (NuGet cache, site-packages, a hoisted parent `node_modules`), so these tools use `sandbox.ts`'s `resolveLibraryPath(libRoots, file)` / `isLibraryPathSafe` instead of `resolveSandboxPath`. The model never passes a file path: it names a package, the tool derives `libRoots` from package-manager metadata, and every file read must realpath beneath one of them; read-mode restricted globs still apply relative to the root. With the sandbox `"off"`, nothing is checked and `permissionGate.ts` prompts (all four tools are in `GATED_TOOL_NAMES`).

- **`ts_lib`** (`libInfo/typescriptLib.ts`) — finds `node_modules/<pkg>` from the project root upwards, resolves `package` + `module` (`"zod/v4"`, `"./v4"` or `"v4"`) with `ts.resolveModuleName` (Bundler, then NodeNext, then Node10 — covers `exports` `types` conditions, `typesVersions`, `types`/`typings`, `@types/*`, and plain `.js` with `allowJs`), builds a program from that one entry file with the extension's own `typescript` (a runtime dependency now; the project's TypeScript is never loaded), and walks `checker.getExportsOfModule`, resolving aliases so `export *`/`export {x as y} from` chains are flattened. Signatures are the declaration's source text up to its body/member list, compacted to one line; JSDoc comes from `ts.getJSDocCommentsAndTags`. Classes/interfaces/enums/object type aliases get member entries (private and `#private` skipped); `type X = Y` and `const x: Y` also list `Y`'s members; namespaces and `export * as ns` recurse (depth 4). `export =` modules show the assigned symbol too. `.d.ts` entry points compile with `noLib` (signatures come from text, not types); JS entry points use the checker for inferred types. The compiler host only sees files passing `isLibraryPathSafe` against the project root, the `node_modules` chain and TypeScript's lib dir — anything else looks absent.
- **`py_lib`** (`libInfo/pythonLib.ts` + `libInfo/py_libinfo.py`) — runs the stdlib-only helper as `python -I py_libinfo.py '<json>'` in the interpreter from `findPythonInterpreter` (`$PI_SMALL_MODELS_PYTHON`, `$VIRTUAL_ENV`, project `.venv`/`venv`/`env`, then `python3`/`python` on PATH — not model-controllable). The helper **never imports the package**: it maps pip names to import names via `importlib.metadata` (`top_level.txt`, `RECORD`, `packages_distributions`), locates modules with `importlib.machinery.PathFinder.find_spec` (pure path search), prefers `<pkg>-stubs` packages and sibling `.pyi` files, and reads source with `ast` — `__all__` if literal, otherwise public local names plus (in `__init__`/`.pyi` only) intra-package `from .x import y` re-exports and `from .x import *`, followed up to 6 levels. It only opens `.py`/`.pyi` files under `sys.path` dirs; `pythonLib.ts` re-checks every reported source path. Compiled modules without stubs are reported, not listed. A leading module path in `symbol` (`requests.adapters.HTTPAdapter`, `adapters.HTTPAdapter`) moves into `module`. Requires Python 3.9+ (`ast.unparse`). `extraSysPath` is a test-only option.
- **`py_list`** — same helper, `cmd: "list"`: every distribution from `importlib.metadata` as `name==version — summary`, filtered by substring; an exact name adds requires, required-by, import names, Requires-Python and URLs.
- **`dotnet_lib`** (`libInfo/dotnetLib.ts` + `libInfo/xmlDocs.ts`) — reads `obj/project.assets.json` (or `artifacts/obj/<name>/`) of the given project, the projects of a given `.sln`/`.slnx`, or every project under the root (first one referencing the package wins); picks the first non-RID target or `tfm`. The package's compile assemblies (`targets[tfm][id/version].compile`) are matched to `.xml` doc files in the package folder (`packageFolders` = the lib roots). Names starting with `System`/`Microsoft` that aren't packages are looked up in the SDK's `packs/<Framework>.Ref/<version>/ref/<tfm>/` (version matching the tfm's major), first as an assembly name, then as a namespace by scanning doc files. **No compiled metadata is read**: `xmlDocs.ts` rebuilds signatures from doc IDs — namespace/type/member, exact parameter types (rendered as C#: keywords, generics, arrays, `Nullable<T>` → `T?`, `@` → `ref`) and `<param>` names; return types, modifiers and undocumented members are unavailable, and class/interface/enum/delegate is a heuristic. Members of undocumented types get a placeholder type entry. The overview scopes to `module`, else a namespace named like the package, else the only namespace, else lists namespaces. Project references (`type: "project"`) are refused with a hint to use `peek`.

## PreviewManagers (`src/tools/previewManagers/`)

`peek`'s per-language outliners, one class per language implementing `PreviewManager` (`types.ts`): `preview(lines, {visibility, includeDocs, maxDepth}) -> {line, text}[]`. **What each language shows is driven by a regex table exported at the top of its file** (`PYTHON_RULES`, `TYPESCRIPT_RULES`, `CSHARP_RULES`, `MARKDOWN_RULES`) — change what peek shows by editing that table, not the scanning logic. `registry.ts` maps extensions to managers (`PREVIEW_MANAGERS`, `previewManagerFor`, `PEEK_EXTENSIONS`); adding a language = a new manager appended there.

- **`python.ts`** (`.py`, `.pyi`) — indentation-based. Shows `class`/`def`/`async def` signatures (every line of a multi-line signature, cut right after the depth-0 `:` so a one-line body is dropped) and their decorators, at module level and inside classes; never function bodies, functions nested in functions, or module-level statements. Tracks brackets and (triple-quoted) strings so `def` text inside a string, or a string line at column 0, can't open/close a scope. Visibility is name-based: plain and `__dunder__` public, `_name` protected, `__name` private; a member is only as visible as its narrowest enclosing class.
- **`braceEngine.ts`** — shared outline scanner for TypeScript and C#. Not a parser: it tracks just enough lexical state (strings incl. TS templates with `${}` holes, C# verbatim/interpolated/raw strings, comments, TS regex literals) to count `{}`/`()`/`[]` reliably, splits statements (on `;`, body braces, and for TS automatic-semicolon-insertion line breaks), and asks the language's `classify(text, container)` what each statement is. One frame per `{`: `members` (statements inside are classified), `verbatim` (shown as written: interfaces, enums, object type aliases), `body` (hidden: function bodies, hidden declarations), `inner` (a brace inside the statement's own text, e.g. a destructured parameter). Bodies render as `{ … }`, initializers as `= …`, arrow/expression bodies as `=> …`; Allman-style `{` lines are folded into the header above.
- **`typescript.ts`** (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`) — top level/namespaces: classes, functions, interfaces, type aliases, enums, namespaces, variables (arrow functions keep their parameter list), `export default`, re-exports. Top-level visibility: `export`/`declare` → public, otherwise private (module-local). Class members: public unless `protected` (protected) or `private`/`#name` (private).
- **`csharp.ts`** (`.cs`) — namespaces (block and file-scoped), types (class/struct/record/interface/enum/delegate) and all members (methods, ctors, operators, properties incl. one-line `{ get; set; }` accessors, indexers, events, fields). `public` → public; `protected`/`protected internal` → protected; `internal`/`private`/`private protected`/no modifier → private; interface members without a modifier → public. Attributes are shown with their declaration; `#region`/preprocessor lines are skipped.
- **`markdown.ts`** (`.md`, `.markdown`, `.mdx`) — headings only (ATX `#` and setext `===`/`---`), so the result is a table of contents; text between headings is dropped. Ignores `#` lines in code fences, HTML comments and YAML front matter. `maxDepth` limits heading levels; `visibility`/`includeDocs` are ignored.

Since this is regex-driven rather than a real parser, unusual formatting can be misread (e.g. a TS object type literal inside a generic on a property, JSX with stray `/`); the tests in `tests/peek_*.test.ts` pin down the supported shapes.

## Cancellation

`fs.readFile`/`fs.writeFile` and `child_process.execFile` all honor `AbortSignal` natively, so `edit`, `insert`, `write` (its write step), and `gitStatus`/`gitDiff` just pass `signal` through. `fs.mkdir`/`fs.rm` don't accept a `signal` at all, so `mkdir`, a non-recursive `remove`, and `write`'s preceding `mkdir({recursive: true})` just check `throwIfAborted()` once up front — reasonable since none is more than a handful of syscalls. A recursive `remove` can walk an arbitrarily large tree, so `removeRecursively` walks entries itself and checks `signal` before each one (same pattern as `list.ts`'s `walk()`). `find` uses fast-glob's `fg.stream()` instead of the promise API and `.destroy()`s it on abort, since the promise form can't be interrupted once started.

## Shared infrastructure

- **`src/ignore.ts`** — `DEFAULT_IGNORE_GLOBS` (fast-glob patterns, used by `find`/`grep`) and `DEFAULT_IGNORE_NAMES` (bare directory names, used by `list`'s manual walk) — both cover `node_modules`, `.git`, `dist`, `build`, `.pi`.
- **`src/mutationQueue.ts`** — `withFileMutationQueue(filePath, fn)` serializes mutating operations on the same file, keyed by its real (symlink-resolved) path. `writeFile`, `editFile`/`editFileMulti`, `insertText`, and `removePath` each wrap their whole read-modify-write in this, so overlapping calls on the same path queue instead of interleaving and silently discarding each other's changes. Modeled on Pi's own built-in `write`/`edit` tools, which have an equivalent helper.
- **`src/toolValidation.ts`** — `withConciseValidationErrors(name, parameters)` builds every tool's `prepareArguments` hook (wired in at each `pi.registerTool({...})` call site in `src/tools/*.ts`). Pi's own schema-validation failure message dumps the tool's complete raw JSON arguments, which is disproportionately expensive for a small model that just needs to know which field was wrong. `prepareArguments` runs *before* Pi's own validation, so a thrown Error here replaces Pi's message entirely; this runs the same `typebox/compile`+`typebox/value` Convert-then-Check Pi itself runs against the tool's `parameters` schema, and on failure throws just the per-field error lines, the names (not values) of the arguments actually received, and — only for an argument a message explicitly names — that one argument's value. A call this accepts falls through unchanged to Pi's own validation, so the success path is untouched.

## Testing

`tests` provides `makeFixture`/`cleanupFixture` for temp directories with a given file tree; every tool test builds a fixture, calls the tool's plain async function, and asserts on the returned result object rather than rendered text. `tests` and `tests`'s symlink-escape tests create real symlinks via `fs.symlink` and `t.skip()` on `EPERM` — expected on Windows without Developer Mode or admin privileges.
